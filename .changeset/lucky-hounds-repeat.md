実在の crontab 201 件で `explain` の出力を人手で確認し（DESIGN.md §3.7）、
見つかった 3 件の不自然な出力を直した。

- 刻みの base が下限から始まってフィールドの全域を覆う場合、`*` と同じものとして
  畳むようにした。Quartz 由来の `0/5` は `0-59/5` に正規化されるため、
  `0 0/5 14 * * ?` が「午後2時台の0分から59分まで5分ごと」になり、
  時の範囲と重なると「午前8時から午前10時まで0分から59分まで30分ごと」と
  「まで」が二重に出ていた。「5分ごと」「30分ごと」に短くなる。
  `*/1` も「1分ごと」ではなく「毎分」になる
  （起点が下限でない `5/15` などの「まで」の重なりは別の原因で、まだ残っている）
- フィールドの幅を超える刻みを「Nごと」と説明しないようにした。
  `*/90` は実際には毎時 0 分に 1 回動くだけなのに「90分ごと」と言っており、
  誤解をそのまま肯定していた。「毎時0分」になる
- 連続する 2 個だけの時のリストで接続が抜けていたのを直した。
  `0 12,13 * * *` が「午後0時と午後1時毎時0分」になっていた
- 時をリストで並べたときの「台」を各時に付けるようにした。
  `* 14,18 * * *` は「午後2時と午後6時台の毎分」となり「台」が午後2時に掛かっていなかった
- `@reboot` のエラーメッセージを、対応漏れではなく日時を持たないため説明できない旨に変えた。
  あわせて `@daily <コマンド>` のようにコマンドが続く crontab の行を受け付けるようにした。
  `crontab -l` の `@reboot` 行はコマンドが付いたまま渡ってくるため

あわせて README に、曜日番号が Unix cron の 0 = 日曜であること
（Quartz は 1 = 日曜なので式をそのまま渡すと 1 つずれる）を明記した。
