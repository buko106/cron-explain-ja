日と曜日の OR 条件まわりの読み違いを 3 つ直す

cron-parser（MIT / harrisiirak）をベンチマークにした差分テストで見つかった欠陥。

**曜日の範囲 `0-7` が日曜だけになっていた。** `0-7` は全曜日を指すが、`7` を先に `0` へ
正規化していたため `0-0`（日曜のみ）になっていた。

```ts
explain("0 0 * * 0-7", { tz: "UTC" }); // '毎週日曜日の午前0時' → '毎日午前0時'
```

**曜日の刻みの起点でも同じ取りこぼしがあった。** `5/1` は「金曜から上限（7 = 日曜）まで」
なので金・土・日だが、上限を 6 と見て金・土だけになっていた。範囲で書いた `5-7` とも
食い違っていた。

```ts
explain("0 0 * * 5/1", { tz: "UTC" }); // '毎週金曜日と土曜日の午前0時'
                                       // → '毎週日曜日、金曜日、土曜日の午前0時'
```

**日と曜日を同時に指定したとき、`explain` だけが OR 条件を取り違えていた。** 片方が全域を
覆っていれば毎日動くのに、日本語は日付を限定したままだった。`next` の結果と食い違う。
タイムゾーン変換も同じ判定を使っていたため、毎日動く式を「15 日だけ」と読んで、月をまたぐ
検査をすり抜けていた。

```ts
explain("0 0 15 * 0-6", { tz: "UTC" }); // '毎月15日の午前0時' → '毎日午前0時'
explain("0 20 15 2 0-6", { tz: "Asia/Tokyo" }); // 誤った式 → CronTimeZoneError
```
